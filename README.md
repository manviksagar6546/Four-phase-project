## 🎯 Why This Project Exists

Instead of building four different apps, I built the **same CRUD functionality four times**, each time at a higher level of abstraction, specifically to understand *what each layer automates* rather than just trusting a framework blindly:

1. **Raw JDBC** — manual SQL, manual parameter binding, manual `ResultSet` mapping
2. **Hibernate (plain ORM)** — object-relational mapping, dirty checking, HQL
3. **Spring Boot + Spring Data JPA** — auto-generated repositories, REST APIs, dependency injection
4. **React frontend** — consuming the REST API over HTTP, with full CORS-aware client-server separation

This progression is intentional — each phase reveals exactly what problem the next layer of abstraction is solving.

## 🏗️ Architecture

```
┌─────────────┐      HTTP/JSON       ┌──────────────────┐      JPA/Hibernate      ┌──────────┐
│   React     │  ───────────────►    │   Spring Boot     │  ───────────────────►  │  MySQL   │
│ (localhost  │  ◄───────────────    │   REST API         │  ◄───────────────────  │ Database │
│   :5173)    │                       │  (localhost:8080)  │                         │          │
└─────────────┘                       └──────────────────┘                         └──────────┘
```

**Layered backend design — separation of concerns:**

| Layer | Class/Interface | Responsibility |
|---|---|---|
| Entity | `Book.java` | Maps a Java object to the `books` table (`@Entity`) |
| Repository | `BookRepository.java` | Persistence layer — CRUD operations, auto-generated by Spring Data JPA (`JpaRepository`) |
| Controller | `BookController.java` | Exposes the repository over HTTP as REST endpoints (`@RestController`) |
| Configuration | `CorsConfig.java` | Allows the React frontend's origin to call the API (browser CORS policy) |

## 📡 API Endpoints

Base URL: `http://localhost:8080/api/books`

| Method | Endpoint | Description | Body |
|---|---|---|---|
| `GET` | `/api/books` | Fetch all books | — |
| `GET` | `/api/books/{id}` | Fetch a single book by ID | — |
| `POST` | `/api/books` | Create a new book | JSON book object |
| `PUT` | `/api/books/{id}` | Update an existing book | JSON book object |
| `DELETE` | `/api/books/{id}` | Delete a book by ID | — |

**Example request body (POST/PUT):**
```json
{
  "title": "Deep Work",
  "author": "Cal Newport",
  "genre": "Productivity",
  "status": "WISHLIST",
  "rating": 4,
  "notes": "Recommended by a friend"
}
```

## 🚀 Getting Started

### Prerequisites
- Java 21 (JDK)
- Node.js + npm
- MySQL 8+
- Maven (or use the included Maven wrapper)

### 1. Database Setup

```sql
CREATE DATABASE personal_library;

USE personal_library;

CREATE TABLE books (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(255) NOT NULL,
    genre VARCHAR(100),
    status VARCHAR(50) DEFAULT 'WISHLIST',
    rating INT CHECK (rating BETWEEN 1 AND 5),
    notes TEXT
);
```

### 2. Backend Setup (Spring Boot)

```bash
cd book-tracker-springboot
```

Update `src/main/resources/application.properties` with your MySQL credentials:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/personal_library
spring.datasource.username=root
spring.datasource.password=your_password_here

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

Run the application:

```bash
mvn spring-boot:run
```

Backend runs on `http://localhost:8080`.

### 3. Frontend Setup (React)

```bash
cd book-tracker-frontend
npm install
npm run dev
```

Frontend runs on `http://localhost:5173`.

> ⚠️ If your frontend runs on a different port, update the `allowedOrigins` value in `CorsConfig.java` to match.

### 4. Open the App

Visit `http://localhost:5173` in your browser. Both the backend and frontend must be running simultaneously.

## 🧠 Key Concepts Demonstrated

- **ORM & Dirty Checking** — Hibernate auto-detects changed fields on a tracked entity and generates `UPDATE` statements without an explicit call
- **Dependency Injection** — Spring creates and injects `BookRepository` wherever it's needed, instead of manual object creation
- **Repository Pattern** — Spring Data JPA generates a full CRUD implementation from an empty interface (`JpaRepository<Book, Integer>`)
- **REST Architecture** — HTTP verbs (`GET`/`POST`/`PUT`/`DELETE`) mapped to specific operations on the same resource URL
- **CORS** — Browser-enforced cross-origin policy, explicitly configured to allow the React dev server's origin
- **Controlled Components** — React form inputs bound to state, with a single `handleSubmit` handling both create and update via conditional logic

## 🐛 Notable Bugs Fixed Along the Way

A few real issues hit and resolved during development (documented here intentionally — debugging is part of the learning):

- JDBC parameter index mismatches between `?` placeholders and `setX()` calls
- Column name typo (`auther` vs `author`) causing silent Hibernate mapping failures
- `ddl-auto=update` silently downgrading a `TEXT` column to `varchar(255)`
- Incorrect `@PostMapping` used instead of `@GetMapping` on a fetch endpoint
- Empty method body on the delete endpoint (compiled fine, did nothing)
- CORS origin mismatch between configured port and actual Vite dev server port
